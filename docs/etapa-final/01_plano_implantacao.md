## Objetivo

Evoluir o Study Hub, implantado na etapa intermediária, de um site publicado para um PortfolioHUB com documentação de implantação, uso orientado do Google Gemini, revisão de acessos, políticas de segurança e testes verificáveis.

## Fases

| Fase | Acao prevista | Evidencia de conclusão |
| --- | --- | --- |
| 1. Planejamento | Comparar o projeto existente com o desafio; delimitar o escopo do site estático e uso do Gemini. | Este plano e registro do Gemini. |
| 2. GitHub | Conferir repositório público, pastas, README e GitHub Pages. | URL pública, arquivos e histórico de commits. |
| 3. Usuários e segurança | Revisar colaboração, autenticação da conta, publicação de arquivos e configurações de segurança. | Capturas com informações sensíveis ocultas e checklist. |
| 4. Compartilhamento | Documentar uso de branches, pull requests, commits e compartilhamento com LinkedIn. | Documentação e, se realizado, PR/commit real. |
| 5. Testes | Conferir site, menu, links, acesso público, ausencia de dados sensíveis e publicação. | Checklist datado e resultados. |
| 6. Apresentação | Gravar video final explicando implantação e desafios; preparar relatório PDF. | Link do novo video e PDF entregue. |

## Decisoes técnicas

- Manter o repositório e site da etapa intermediária, preservando o histórico de commits.
- Usar o GitHub para armazenar código e controlar alterações. GitHub Pages pública a interface de consulta.
- **Não adicionar um login ficticio**: a autenticação de quem edita se da no GitHub; visitantes consultam apenas conteúdo público.
- Consultar o Gemini para revisar o plano de implantação, identificar riscos e recomendar testes; avaliar criticamente suas respostas.
- Não compartilhar dados pessoais ou credenciais com ferramentas de IA.

## Riscos e respostas

| Risco | Medida |
| --- | --- |
| Perda ou substituicao de arquivos | Copia de segurança e commits descritivos. |
| Publicação indevida | Revisão do conteúdo antes do commit. |
| Configuração de acesso excessiva | Conferencia de colaboradores e privilegios. |
| Erro após publicação | Teste da página, links e possibilidade de reverter por Git. |
| Orientacao incorreta da IA | Conferir configurações e funcionalidades reais no GitHub. |

## Resultado esperado

Ao terminar, o Study Hub deve continuar acessível em seu endereco público, com suas configurações documentadas, critérios de segurança aplicados conforme possível e um relatório final com evidências honestas do que realmente foi executado.
